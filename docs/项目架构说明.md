# UVmicroscopy 项目架构说明

## 1. 项目目标与运行形态

本项目是一个基于 PyQt5 的显微切片采集控制系统，核心能力包括：

- 相机采集（单拍、连续、ZStack 触发采集）
- 三轴位移台与微调轴控制（X/Y/Z/ZM）
- 光源与泵控制
- Mosaic 扫描与 Mosaic+Cut 联合流程
- 图像显示、拼接预览与本地保存

运行形态是单个 GUI 主进程，内部通过多个 QThread + Queue 组成生产者/消费者模型。

## 2. 总体分层

从职责上可分为 5 层：

1. 交互层（UI）
2. 编排层（Weaver）
3. 设备执行层（Camera / DO）
4. 显示与存储层（DnS）
5. 基础设施层（日志、异常、配置、动作协议）

对应主要文件：

- 入口与线程装配: SliceScanner.py
- UI 与配置管理: MainWindow.py, my_ui.py, ui2.ui
- 编排线程: ThreadWeaver.py
- 相机线程: Camera.py
- 位移/IO 线程: ThreadDO_150mm.py
- 显示与保存线程: ThreadDnS.py
- 动作协议: Actions.py
- 公共工具: Generaic_functions.py

## 3. 线程与队列模型

### 3.1 线程角色

- 主线程（GUI）: 响应按钮、更新 UI、发起高层动作
- WeaverThread: 任务编排与流程控制（Snap/Live/Mosaic/Mosaic+Cut）
- CameraThread: 相机参数与采集执行
- DOThread: 位移、光源、泵、振动刀、触发输出
- DnSThread: 图像显示、Mosaic 合成、文件保存

### 3.2 队列通道

在 SliceScanner.py 中统一创建并注入：

- CQueue / CBackQueue: Weaver <-> Camera
- DOQueue / DOBackQueue: Weaver/GUI <-> DO
- WeaverQueue: GUI -> Weaver
- DnSQueue / DnSBackQueue: Weaver -> DnS（以及部分回传）

### 3.3 动作协议

通过 Actions.py 的轻量对象约定跨线程消息：

- WeaverAction, CAction, DOAction, DnSAction, EXIT

动作协议是当前系统解耦的核心，保持了线程间的低耦合和可替换性。

## 4. 启动与生命周期

### 4.1 启动阶段

1. SliceScanner.py 初始化日志与 crash 追踪（faulthandler）
2. GUI(MainWindow) 创建并绑定控件事件
3. 启动 Weaver/DO/Camera/DnS 四个线程
4. 每个线程进入 QueueOut 循环，等待动作

### 4.2 退出阶段

- GUI closeEvent 调用 Stop_allThreads()
- 向各队列发送 EXIT
- 保存 config.ini
- 记录 exit_reason 与异常链

## 5. 关键业务流程

### 5.1 Snap

主路径：

1. Weaver 下发 Stream_on、LightON
2. Camera 执行 FiniteAcquire
3. DnS 执行 Display_Snap
4. 可选保存 Snap tif

### 5.2 Live

- Weaver 启动 Camera 连续采集
- DnS 持续刷新图像显示

### 5.3 Mosaic

主路径：

1. PreMosaic/LoadTileFlag 准备扫描网格与 tile_flag
2. Weaver 双层循环遍历 tile（蛇形扫描）
3. 每 tile 顺序执行：Xmove2 -> Ymove2 -> LightON -> FiniteAcquire -> Zstack -> LightOFF
4. DnS 使用 Display_Mosaic 更新拼图并保存 tile 原图
5. 结束后 Save_Mosaic 输出 coase 图，restart_tilenum

### 5.4 Mosaic+Cut

- 在 OneImagePerCut 中交替执行 SingleCut 与 Mosaic
- SingleCut/RptCut 负责切片动作（振动刀、Y 轴慢速切割、Z 位置控制）

## 6. 数据与文件输出

当前输出主要在本地 DIR 下：

- mosaic/ 目录：每个 tile 的 tif 原图
- 根目录：sliceNcoase.tif（拼接概览图）
- 根目录：slice-*-agarTiles*.bin（tile 标记）
- log_files/：运行日志
- crash_breadcrumb.log / crash_dump.log / exit_reason.log：故障追踪

## 7. 配置与参数体系

config.ini 保存绝大多数 UI 参数，包括：

- 扫描范围: XStart/XStop/YStart/YStop
- 成像参数: Exposure/Gain/PixelFormat/Width/Height
- 扫描参数: XFOV/YFOV/Overlap/Zstack
- 机械参数: XSpeed/YSpeed/ZSpeed, SliceSpeed, SliceZDepth
- 保存参数: DIR, Save

MainWindow.py 使用 QSettings 读写，并通过定时防抖自动持久化。

## 8. 日志与可观测性设计

### 8.1 常规日志

- LOG 类写入 log_files/log_*.txt

### 8.2 Breadcrumb 日志

- write_breadcrumb 输出高频结构化事件
- 用于排查跨线程时序、硬件调用边界、崩溃前路径

### 8.3 异常处理

- report_exception 统一输出异常链与根因
- 主线程与子线程均挂接异常钩子

## 9. 架构特点与已知风险

### 9.1 架构优点

- 通过 QueueAction 把 UI 与硬件调用解耦
- 线程职责边界清晰：编排、设备、显示分离
- 出错时可通过日志恢复关键执行路径

### 9.2 主要风险点

- 无硬件位置闭环：位移台当前位置主要由软件状态更新
- 相机触发偶发超时会导致空帧，可能引发单 tile 丢失
- 线程异步时序可能造成“日志顺序与视觉顺序不一致”

## 10. 维护建议

1. 新增功能优先通过 Action + Queue 扩展，避免跨线程直接调用
2. 设备层保持“纯执行”，流程判断放在 Weaver
3. DnS 层仅处理显示与存储，不承担流程决策
4. 为关键路径统一增加 tile_id（移动、采集、保存一致编号）
5. 对相机空帧引入重试策略与降级标记，避免静默缺图

## 11. 快速定位入口（给新开发者）

建议从以下顺序阅读代码：

1. SliceScanner.py（线程装配与入口）
2. MainWindow.py（参数来源与 UI 绑定）
3. ThreadWeaver.py（核心业务流程）
4. ThreadDO_150mm.py（位移与 IO 细节）
5. Camera.py（采集逻辑）
6. ThreadDnS.py（拼接显示与保存）
